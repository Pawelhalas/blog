## Loose ends and known imperfections

**Archives is a soft 404.** `showArchives: false` makes `/archives/` render the
404 page, but Astro emits it as a static file so it returns **HTTP 200**, not
404. It is unlinked and out of the sitemap, so the risk is low. A genuine 404
means deleting `src/pages/archives/` — a deletion, so ask first.

**List descriptions are 16px, rule 7 asks for ≥18px.** Read as "body copy = post
prose, not index summaries", so descriptions do not compete with 18px titles.
Flagged, never decided. Pawel has not ruled.

**The tag lattice reads sparse.** Five tags, four of them on one post each. This
is a content problem, not a layout bug — the tag vocabulary rule of 2–3 tags per
post with reuse preferred is what fixes it over time.

**`IMG_9875.jpg` (3.5MB) sits untracked** in `src/assets/images/`. The committed

## Traps worth not rediscovering

- **Typora escapes frontmatter.** It writes `\---` instead of `---`, which makes
  the YAML never parse and the post fail schema validation. Happened on both
  posts. Check after every edit in Typora.
- **`astro check` does not catch broken image paths.** Typora inserts absolute
  local paths when an image is dragged in; Astro treats them as external URLs and
  passes them through, so the build reports 0 errors while shipping dead images.
  Image paths in posts must start with `../../assets/`.
- **A `?` in a filename breaks the content loader outright.** Astro truncates at
  the `?` and fails with `ENOENT`. Filenames are permalinks: ASCII, lowercase,
  hyphens.
- **`site.lang` alone does nothing.** `Layout.astro` reads
  `Astro.currentLocale ?? site.lang`, and `Astro.currentLocale` comes from
  `astro.config.ts`. Both must move together.
- **Two scripts in `src/scripts/` need `export {}`.** Without it TypeScript treats
  them as global scripts and identically named helpers collide — `astro check`
  fails. `noise.ts` carries the comment explaining this.
- **The dev server's `/_image` endpoint does not render in screenshots.** Verify
  images against a built `dist/` served statically, not the dev server.
- **GitHub's GraphQL API had an outage during this session.** `gh pr create` failed
  with 503 while REST was healthy; PRs #10–#12 were created via
  `gh api repos/.../pulls`. Worth trying if `gh pr` misbehaves.
